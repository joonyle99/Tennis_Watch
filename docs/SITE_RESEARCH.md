## 1. 사이트 구조

### 1.1 데이터 단위는 "서비스(공고)"다 [확인]

사이트에는 "시설"이나 "코트" 엔터티가 따로 없고, 예약 단위는 `rsv_svc_id`(예: `S261109111743936593`)로 식별되는 **서비스**다. 테니스장은 보통 `시설 × 코트 × 시간대 구분 × 이용기간` 조합마다 서비스가 하나씩 등록된다.

실제 서비스명 예시:

- `홍은테니스장 평일 주간 11월16일~30일`
- `가좌테니스장 평일 야간 B코트 11월16일~30일`
- `11/16~11/30 장충테니스장 4번코트(평일주간)`
- `잠원 한강공원 테니스장 2번 코트 평일`
- `테니스장1(평일)-2026년 응봉공원(대현산배수지)`

코트 번호와 시간대 구분은 **서비스명 자유 텍스트에만** 들어 있고 표기 방식이 시설마다 다르다. 구조화된 코트 필드는 없다.

운영 방식도 시설마다 다르다 [확인]:

- 반월 단위로 새 서비스를 등록하는 시설(홍은·가좌·장충·도로사업소): 회차마다 `rsv_svc_id`가 새로 생김
- 연 단위 서비스 하나를 유지하는 시설(응봉공원: 이용기간 2025-12-01 ~ 2026-12-31)
- 월 단위(잠원한강: 2026.11.01 ~ 11.30)

## 2. 공식 공공데이터 [확인]

서울 열린데이터광장에 원본 시스템이 "공공서비스예약"인 공식 데이터셋이 있다.

- 데이터셋: **서울시 체육시설 공공서비스예약 정보 (OA-2266)**
- URL: https://data.seoul.go.kr/dataList/OA-2266/S/1/datasetView.do
- 제공: 서울특별시 디지털도시국 정보시스템과
- 이용허락: **공공누리 1유형 (출처표시, 상업적 이용 및 변경 가능)**
- 갱신: 비정기(수시, 자료변경시). 조사일 기준 데이터 갱신일 2026.11.14.
- 포털 설명: "이용종료된 데이터는 제외", "연계시간 차이로 일부 차이가 날 수 있음"

포털 미리보기로 확인한 전체 624건 중 테니스장은 **313건**으로 사이트 목록의 총 건수와 일치했고, 고유 장소명은 40개였다.

### 2.2 Open API 호출 [확인 — 2026-11-14 사용자 PC에서 실행]

조사용 클라우드 환경은 443 포트 HTTPS만 통과시켜 직접 호출하지 못했고, 사용자가 발급받은 일반 인증키로 로컬에서 호출한 결과로 확인했다.

```
GET http://openapi.seoul.go.kr:8088/{인증키}/json/ListPublicReservationSport/{시작}/{끝}/테니스장
```

- 평문 HTTP, 8088 포트. 마지막 경로 값은 소분류명(`MINCLASSNM`) 필터다.
- 응답 구조:

```json
{"ListPublicReservationSport": {
  "list_total_count": 313,
  "RESULT": {"CODE": "INFO-000", "MESSAGE": "정상 처리되었습니다"},
  "row": [{"SVCID": "S251121100349891778", "SVCSTATNM": "예약마감", "...": "..."}]
}}
```

- `list_total_count`는 313으로 사이트 목록 총 건수와 일치했다.
- 한 번에 최대 1,000건까지 요청할 수 있다(포털 안내 화면). 테니스장 전체를 요청 1회로 받을 수 있다.
- 오류 응답은 `json`으로 요청해도 **XML**로 온다: `<RESULT><CODE>INFO-100</CODE><MESSAGE>인증키가 유효하지 않습니다. ...</MESSAGE></RESULT>`. 파서는 JSON 파싱 실패 시 이 형식을 처리해야 한다.
- 미리보기와 다른 점:
  - 일시 값 끝에 `.0`이 붙는다: `"RCPTBGNDT": "2025-12-02 09:00:00.0"`
  - 좌표 `X`(경도), `Y`(위도)가 포함된다: `"X": "127.02182026085195", "Y": "37.5569473910838"`
  - `RONUM`은 없다.
  - `USETGTINFO` 앞에 공백이 있다(`" 제한없음"`). 문자열은 trim한다.
  - `DTLCONT`에 `\r\n` 줄바꿈이 보존된다.
- 일시 값에는 시간대 표기가 없다. 한국시간(KST)으로 해석한다 [추정 — 사이트 표시값과 일치].

### 2.3 확인하지 못한 것 [미확인]

- **일일 호출 한도**: 포털 안내에 "하루 최대 1,000건"은 실시간 지하철 API에만 적혀 있고, 일반 API 한도는 명시가 없다. "이용 제약 없이 계속 사용하려면 활용사례 등록" 문구가 있어 제약이 있을 수 있다. 5분 주기(하루 288회)로 시작하고 제한 응답이 오면 주기를 늘린다.
- **갱신 지연**: "연계시간 차이"가 실제로 몇 분인지 측정하지 않았다. 운영 초기에 Open API 상태와 상세 페이지 상태를 비교해 측정한다.
- 미리보기 엔드포인트(`/dataList/dataView.do`)는 포털 내부용이므로 운영 수집에는 쓰지 않는다.

```js
};
```

검증: 상세 페이지에서 받은 세션 쿠키와 `#aform` 값 그대로 `selectListReservCalAjax.do`에 POST를 **1회** 보냈다. 응답은 `302`였고 `Location`은 `/management/ipRedirect.do?threatGb=DNP&threatTt=비정상 접근으로 인한 차단 알림&threatCn=비정상 접근으로 파악되어 서비스가 제한되었습니다`였다. 이후 목록·상세 조회는 계속 정상 응답했다(IP 차단은 발생하지 않음).

이것은 예약 달력과 시간대 조회에 대한 자동화 접근을 사이트가 의도적으로 막아 둔 것이다. 프로젝트 지침("CAPTCHA, 로그인 보호, 접근 제한을 우회하지 않는다")에 따라:

- 보호 스크립트를 분석·재현해 토큰을 만드는 방식은 구현하지 않는다.
- Playwright로 실제 브라우저를 띄워 달력을 읽는 방식도 같은 보호를 우회하는 것이므로 **구현하지 않는다.** 이 방식은 시험하지도 않았다.

참고로 페이지 내 JS에서 확인한 달력 응답 구조는 다음과 같다(코드상 확인, 실제 응답은 받지 못함): `resultListDays[].{YMD, SVC_RESVE_CODE}`, `resultListTm[YMD].{RCEPT_POSBL_YN, RESVE_POSBL_CNT, REG_TOTAL_CNT, RCRIT_NMPR_CNT}`.

## 5. 법적·정책적 주의사항

- **robots.txt** [확인]: `User-agent: *`에는 `Disallow: /web/bbs/selectPageListBbs.do`(게시판 목록)만 있다. 검색 목록 3종은 `Googlebot`에 대해서만 Disallow다. 상세 페이지(`selectReservView.do`)는 제한이 없다.
- **명시적 요청 빈도 제한** [미확인]: 문서화된 rate limit은 찾지 못했다. 이번 조사 수준(2~3초 간격 15회)에서는 차단이 없었다.
- **이용약관** [미확인]: 사이트 푸터에서 이용약관 링크를 찾지 못했다(개인정보처리방침만 있음). 자동 수집 관련 약관 조항은 확인하지 못했다.
- **매크로 금지** [확인]: 시설 상세내용에 "부정한 방법(매크로)에 의한 예약 적발 시 코트 이용 제한"이 명시되어 있다(한강공원 테니스장). 본 프로젝트는 예약을 자동화하지 않고 사용자가 직접 예약하므로 해당하지 않지만, 자동 예약은 절대 구현하지 않는다는 원칙의 근거가 된다.
- **공공누리 1유형** [확인]: OA-2266 데이터는 출처 표시 조건으로 자유 이용 가능하다. 대시보드에 출처(서울특별시, 서울 열린데이터광장)를 표시한다.
- 개인정보: 수집 대상에 개인정보는 없다. 담당자 전화번호(`TELNO`)는 공개 문의처다.

## 9. 권장 수집 방식

1. **1순위 — 서울 열린데이터광장 Open API (OA-2266)**: 전체 목록과 상태를 요청 1~2회로 받는다. 공식 제공 채널이고 이용허락이 명확하다. 인증키는 `SEOUL_OPENAPI_KEY` 환경변수로 관리한다.
2. **2순위 — 상세 페이지 HTML**: 관심 서비스에 한해 `selectReservView.do`를 조회해 상태를 교차 확인한다. 오픈 직전에만 주기를 줄인다.
3. **대체 — 목록 HTML**: Open API를 쓸 수 없을 때만. 전체 목록은 53페이지이므로 하루 1회, 평소에는 자치구·상태 필터로 범위를 좁힌다.
4. **Playwright는 수집에 사용하지 않는다.** 목록·상세는 서버 렌더링이라 필요 없고, 달력은 4장의 이유로 대상이 아니다. E2E 테스트 용도로만 쓴다.

수집 주기 제안(확정은 Open API 한도 확인 후):

| 대상 | 주기 |
|---|---|
| Open API 전체 목록 | 5분 |
| 관심 서비스 상세 페이지 | 5분, 요청 간 2초 이상 간격 |
| 접수 시작 10분 전 ~ 시작 후 5분 | 해당 서비스 상세 페이지만 1분 |
| 목록 HTML 전체(대체 경로) | 하루 1회 |

공통: 식별 가능한 User-Agent, 타임아웃 15초, 실패 시 지수 백오프, 동시 요청 1개, 차단 페이지(`ipRedirect.do`) 응답을 감지하면 즉시 수집을 멈추고 오류 알림.

## 10. 사용자 확인이 필요한 사항

1. **빈 코트 알림 범위 축소 수용 여부**: 코트·시간대 단위 취소표 알림은 이 사이트에서 정책상 구현할 수 없다. 공고 단위 "접수 재개" 알림으로 대체하는 안을 수용하는지.
2. ~~Open API 인증키~~ — 해결. 사용자가 일반 인증키를 발급받았고 호출을 확인했다. 키는 `.env`의 `SEOUL_OPENAPI_KEY`로 관리하며 저장소에 넣지 않는다.
3. ~~관심 시설~~ — 해결. 강남구 테니스장(조사일 기준 16건): 마루공원, 동부도로사업소 테니스장, 탄천물재생센터.
   - 마루공원: 연 단위 공고(1~3면 × 조명 유무)가 상시 접수중이라 공고 상태 변화가 드물다. 오픈·접수 재개 알림 효과가 제한적이다.
   - 동부도로사업소: 반월 단위로 새 공고가 등록되고 예약마감이 실제로 발생한다. 오픈 알림과 접수 재개 알림에 적합하다.
   - 탄천물재생센터: 선정방법이 심사이고 일원1동·개포3동 주민 전용이다.
