# Tennis Watch — PRD

개인 1명이 쓰는 테니스 코트 예약 모니터링 서비스. 예약 오픈 일정과 접수 상태를 수집해 Telegram으로 알린다. 예약은 사용자가 사이트에서 직접 한다.

## 범위

| 항목 | 내용 |
|---|---|
| 형태 | 웹 대시보드(Next.js) + 백그라운드 수집 서버(FastAPI) |
| MVP 사이트 | 서울시 공공서비스예약 |
| 관심 시설 | 강남구 마루공원, 동부도로사업소 테니스장 |
| 알림 | Telegram Bot API |
| 배포 | Docker Compose |
| 구현하지 않음 | 회원가입, 결제, 자동 예약, Discord, Slack |

2차 대상(MVP 이후): 송파구시설관리공단, 대치유수지체육공원, 올림픽테니스장, 성남도시개발공사. 사이트별 Adapter로 추가한다.

## Phase 1에서 확정된 제약

근거는 [SITE_RESEARCH.md](SITE_RESEARCH.md).

- **코트·날짜·시간대별 잔여는 수집하지 않는다.** 사이트가 달력 조회에 대한 자동화 접근을 차단하며, 이를 우회하지 않는다. 슬롯 상태는 `UNKNOWN`으로 두고 사용자가 수동 입력할 수 있게 한다.
- **빈 코트 알림은 공고 단위 "접수 재개" 알림이다.** 공고 상태가 `예약마감 → 접수중`으로 바뀌면 알린다. 어느 날짜·시간이 비었는지는 알 수 없다.
- **예약 오픈 방식은 두 가지다.**
  - 롤링 오픈(마루공원): 이용일 14일 전 14시에 하루치가 열린다. 규칙은 상세 페이지에서 자동 수집된다. 관심 이용일마다 오픈 시각을 계산해 알린다.
  - 회차별 공고(동부도로사업소): 반월 단위 공고가 접수 시작 일시에 한 번에 열린다. 접수 시작 일시는 자동 수집, 반복 규칙(매월 10일·25일 00:00 추정)은 수동 등록 후 실제 공고와 대조한다.
- **목록은 서울 열린데이터광장 Open API(OA-2266)를 우선 사용**하고, 인증키가 없으면 HTML 목록으로 대체한다.

## 기능 요구사항

| ID | 기능 | 비고 |
|---|---|---|
| FR-01 | 테니스장 검색, 관심 시설·코트 관리, 수동 시설 등록 | 코트는 공고명에서 추출 후 수동 확인 |
| FR-02 | 예약 오픈 일정 관리와 알림(1일·1시간·10분 전, 실제 오픈 확인) | 알림 시점은 설정에서 변경 |
| FR-03 | 예약 가능 상태 `AVAILABLE` `UNAVAILABLE` `NOT_OPEN` `CLOSED` `UNKNOWN` | 자동 수집은 공고 단위만 |
| FR-04 | 접수 재개 감지 `UNAVAILABLE → AVAILABLE` | 최초 수집, 수집 실패 복구, `UNKNOWN → AVAILABLE`에는 알리지 않음 |
| FR-05 | 자동 수집 + 수동 입력·보정 | 수동값은 덮어쓰지 않고, 충돌 시 양쪽 보존 |
| FR-06 | Telegram 알림 | 연결 테스트, 중복 방지, 재시도, 429 처리, 발송 이력 |
| FR-07 | 관심 조건(시설, 코트, 날짜, 요일, 시간대, 알림 종류) | 최소 연속 이용 시간은 수동 슬롯에만 적용 가능 |
| FR-08 | 대시보드, 달력, 관심 설정, 시스템 설정 | 외부 접근 시 인증 적용 |

## 원칙

- 시간은 UTC로 저장하고 화면에는 한국시간으로 표시한다.
- 확인하지 않은 데이터를 추측해 채우지 않는다.
- 사이트에 과도한 요청을 보내지 않는다. CAPTCHA, 로그인 보호, 접근 제한을 우회하지 않는다.
- 보안 정보는 환경변수로 관리한다.

## 개발 단계

1. 사이트 기술 검증 — 완료
2. 백엔드 기반(FastAPI, SQLite, 모델, Adapter) — 완료
3. 데이터 수집 엔진(자동 수집, 수동 입력, 상태 비교, 스케줄러) — 완료
4. Telegram 알림 — 완료 (설정 방법: [TELEGRAM_SETUP.md](TELEGRAM_SETUP.md))
5. 웹 대시보드
6. 테스트 및 배포(Docker Compose, 백업, 재시작 복구)
